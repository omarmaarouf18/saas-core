## Decisions taken
- **GOVULNCHECK_VERSION=v1.8.0.** `go list -m -versions golang.org/x/vuln` lists v1.9.0 as newest, released 2026-10-11T03:39:53Z (5 days before today, 2026-10-16), so it fails the "at least 14 days old" rule. v1.8.0 was released 2026-09-08T20:52:42Z (38 days old). It is also the version the local `~/go/bin/govulncheck` already reported. Literal output in Verification, item 1.
- **Cache key includes the Go version** (and, for gosec, the x/tools version): `govulncheck-<v>-go<GO_VERSION>`, `gosec-<v>-xtools-<v>-go<GO_VERSION>`. A bump of any input gives a fresh directory, so no stale binary is reused.
- **Drift guard moved into `scripts/check-go-version.sh`**, used by both the hook and the CI "Verify Go Version Consistency" step. Before, CI had its own hard-coded copy, which would have kept drifting. Same messages as before; two additions: it requires at least one `go-version:` line in ci.yml, and accepts any quoting (`'x'`, `"x"`, bare), so reformatting a line cannot make it escape the check.
- **ci.yml keeps literal `go-version: '1.26.9'` lines** (checked by the guard) instead of reading versions.env at runtime. The prompt asks the guard to check ci.yml against versions.env; literal lines stay greppable for Renovate.
- **Scripts are invoked as `bash scripts/<x>.sh`** in the hook, CI and Makefile, and are also marked 100755 in the index. This repo has `core.fileMode=false`, so a new file's +x bit is not recorded by `git add`. The first item-2 commit stored `install-tools.sh` as 100644, which would have broken `./scripts/install-tools.sh` on a CI checkout; fixed in a separate commit.
- **Lock message text** changed in both places to `waiting for CI lock: <file> is held by another gate run (make ci or git push)`. It stays identical between `make ci` and the hook, and is no longer wrong when the holder is a push.
- **Delete-only detection** treats a local sha that is all `0`s as a delete (works for SHA-1 and SHA-256). Empty stdin or any non-zero local sha runs the full gate. stdin is read only for real pushes (`$1` set); `make ci` never reads stdin.
- **TEST_DB_SUFFIX is sanitized**: characters outside `[A-Za-z0-9_-]` become `_`. The main worktree's directory is `SaaS prototype`, and MongoDB database names cannot contain a space; the literal recipe from the prompt would give `SaaS prototype-<pid>`. Result: `SaaS_prototype-<pid>`, `WF-02-<pid>`. The variable is printed at gate start.
- **`make commit` moved into `scripts/commit.sh`**, which reads `FILES`/`MSG`/`MSG_FILE` from the environment (GNU make exports command-line variables to recipes), never via make text substitution. As a side effect, a multi-line or quote-containing `MSG` also works now (F3).
- **`make commit` commits through a temporary index** (HEAD + the real index entries under FILES), not `git commit --only`. The first item-7 version used `--only`, which rebuilds new entries from disk and dropped an index-only `--chmod=+x` (with `core.fileMode=false`). The temp-index version commits FILES exactly as staged (content and mode) and leaves the real index alone, so other staged paths stay staged.
- **`agent-worktree.sh new`** warns instead of failing when `flutter pub get` fails (not only when flutter is missing). The worktree already exists at that point, so failing would leave a half-reported state. It runs flutter with `GIT_DIR`/`GIT_WORK_TREE` unset, same reason as the hook. WF-01.md lists no other per-worktree setup; the tool cache is per user, not per worktree.
- **Acceptance for item 4(a)** ran as a real `git push` from a scratch clone of this branch (a standalone repo on non-agent branch `wf02-push-probe`; a linked worktree or `agent/*` branch is blocked by Layer B). Its `.git/ci.lock` was a symlink to the main repo's `ci.lock`, so the push waited on the real shared lock and its full gate stayed serialized with other agents' gates.
- **Acceptance for item 5 (main worktree)** used `git -c core.hooksPath=<WF-02>/.githooks push ... --delete probe` from the main worktree, because the main worktree still has the old hook until this branch is merged. This points at the new hook; it does not bypass it.
- Items 1–6 were committed with one-line `MSG`s and no `Co-Authored-By` trailer: the old `make commit` cannot take a multi-line MSG (F3). From item 7 on, commits use `MSG_FILE` with the trailer.
