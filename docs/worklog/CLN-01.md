   - 117–159: per-feature delivery records under "Architecture Table".
   - 178–184: pass narratives under "Done & Verified".

   - 311–315: records misfiled under "Request Field Naming".
   - 334–1249: everything after the Standing Working Rule list.

   Not archived, because they are current state that the slim file condenses: lines 1–116 (header, docs system,
   tooling, CI parity, architecture), 160–177 and 185–251 (feature status intro, deferred decisions, refactor
   backlog), 294–310 (request-field table), 316–333 (standing rules). They stay readable at `1e7692ab...` in git.
   The slim file condenses them.
2. **Archive format.** Each slice sits between `<!-- CLN-01 slice N begin/end -->` markers, so the diff proof can
   extract it mechanically. The header and the slice table are the only non-verbatim text.
3. **Links in the proposed file** are written relative to the repo root, because the file is meant to replace
   `AI_CONTEXT.md` at the root. Until the swap, those links resolve wrongly from `docs/history/`. That is expected.
4. **Workflow content** is not restated in the proposed file. It points to `docs/WORKFLOW.md` (WF-01) and `CLAUDE.md`.
5. **Two follow-up commits on the proposed file** (commits 3 and 6 below), instead of rewriting commit 2. While
   building the inventory I found that `jobs_handlers.go` cites "AI_CONTEXT.md backlog" for the `CompleteJob` legacy
   fallback. I also found that the Backend-Lows item "hub.Run() shutdown path" was still open but had been dropped.
   The task forbids rebasing and asks for no history rewriting, so both are separate commits. The final commit list is
   therefore 7 commits, not the 5 the task listed.
6. **Inbound-link counts** in `docs/README.md` use basename text matches (`grep -l`). They exclude `docs/history/`
   (the archive repeats old mentions) and the file itself. The method is described in that file.
7. **Inventory evidence blocks** are generated by a script. Each `bash` block is bash's `declare -f` rendering of
   the function that actually ran, which is why it shows normalized `;` and indentation. The `text` block under it
   is that run's captured stdout and stderr.
