## Follow-ups / out-of-lane findings
- **Local gate vs CI policy discrepancy on stdlib vulnerabilities**:
  Currently, `scripts/govulncheck-module.sh` prints a `WARNING` on called stdlib findings but exits 0, while GitHub CI (`.github/workflows/ci.yml`) treats called stdlib findings as blocking failures. We now have two consecutive incidents (GO-1-26-10 for GO-2026-6809 in crypto/x509 and GO-1-26-11 for GO-2026-6859 in net/http) where local checks passed cleanly with `make check`, but the integration branch went red immediately upon push to GitHub CI, blocking subsequent agent branches until an emergency toolchain bump landed.
  *Recommendation for repo owner*:
  It is recommended that the pre-push gate (or `make check` when `CI_SCOPE=full` or on push) also block on called stdlib vulnerabilities by default, but provide an explicit opt-out environment variable (e.g., `ALLOW_STDLIB_VULN=1` or `IGNORE_STDLIB_VULN=1`) for situations where an upstream Go patch has not yet been released. This prevents developers and agents from pushing commits that will predictably fail CI, saving CI and developer time while preserving an escape hatch when needed.
