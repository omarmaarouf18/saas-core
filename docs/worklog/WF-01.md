`make ci` could export `TEST_DB_SUFFIX=$(basename worktree)-$$`. Once that lands, the lock could be relaxed.

## 6. Findings, unverified items, open questions

**Findings (not fixed: out of handoff scope or need an owner decision):**
- **F1:** the real `git push` pre-push gate does **not** take `ci.lock`; only `make ci` does. The owner's `make push` from
  main can therefore run integration tests against the shared Mongo/Redis while an agent's `make ci` is running.
  Fix options: `flock` the hook body, or have `make push` run `make ci` and push with the gate skipped. The second
  conflicts with the no-`--no-verify` rule, so the first is simpler.
- **F2:** delete-only pushes (`git push <remote> --delete <ref>`) also run the full ~4-minute gate.
- **F3:** `make commit` breaks on a multi-line `MSG` (`/bin/sh: -c: line 9: unexpected EOF while looking for matching` + a backquote,
  `make: *** [Makefile:57: commit] Error 2`). As a result, a `Co-Authored-By` trailer cannot be added through `make commit`.
- **F4:** in a freshly created worktree, `make ci` fails at the dart format step (86 files reported) until
  `frontend/.dart_tool` exists, presumably via `cd frontend && flutter pub get`. Neither `agent-worktree.sh new` nor
  WORKFLOW.md mentions this. I inferred the cause from the stopped agent's two logs and did not reproduce it.
- **F5:** the stopped agent left `/tmp/wf01-ci-main.log`, `/tmp/wf01-ci-wt.log` and `/tmp/wf01-ci-wt2.log`. I left them in place for the owner.

**Unverified:**
- Why the piped `timeout 10 make ci | head -5` printed nothing (the buffering explanation is a guess). The unpiped
  re-run proves the waiting line is printed.
- F4's exact cause (see above).
- The channel names in the two `*_docker_integration_test.go` files were not inspected in detail.
- The two fix commits were not run through `make worktree-remove` against the real repo's missing-dir path. They were exercised only in a scratch
  repo and, for the force path, by the check-9 cleanup.

**Open questions for the owner:**
1. F1: should the pre-push hook take `ci.lock` itself, so that real pushes are serialized against agents' `make ci`?
2. F3: should `make commit` accept multi-line messages (e.g. `MSG_FILE=`), or is the raw git sequence the intended route for trailers?
3. F4: should `agent-worktree.sh new` (or WORKFLOW.md §1) run or document `flutter pub get` for new worktrees?
4. Step 3: implement the `TEST_DB_SUFFIX` / unique-ID change for the ADR-0006/7/8 Redis tests (a `services/**` lane task)?
